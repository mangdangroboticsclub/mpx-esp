# Mini Pupper ESP32 Trajectory Tools

Tools for extracting joint-angle trajectories from HDF5 files (generated by the
[minipupper-backflip](../../Quadruped/Backflip/minipupper-backflip/) trajectory
optimizer) and deploying them to the Mini Pupper ESP32 firmware.

## Files

| File | Purpose |
|---|---|
| `hdf5_tools.py` | Core library — HDF5 I/O, angle extraction, auto-calibration, format conversion |
| `generate_delta_trajectory.py` | **Primary tool** — HDF5 → delta-format C header for firmware (calibration-safe REF+DELTA) |
| `extract_hdf5.py` | CLI — inspect/debug: summary, JSON, CSV, or absolute-format C header |
| `flash_trajectory.py` | CLI — real-time streaming to ESP32 via HTTP, or load into teach buffer |

## Quick Start

```bash
# 1. See what's inside any trajectory file:
python extract_hdf5.py trajectory.hdf5 --summary

# 2. Generate a calibration-safe delta-format C header (recommended):
python generate_delta_trajectory.py trajectory.hdf5 --name MY_TRAJ -o ../main/

# 3. Stream trajectory to the robot in real time over WiFi:
python flash_trajectory.py trajectory.hdf5 --upload --host 192.168.4.1

# 4. Dry-run preview without connecting:
python flash_trajectory.py trajectory.hdf5 --upload --dry-run --frames 10
```

## Recommended Workflow: `generate_delta_trajectory.py`

This is the **primary tool** for deploying trajectories to the firmware. It
produces a C header in the **delta format** (same pattern as Backflip 3 in
`hardcode_backflip_angle.h`), which is calibration-safe.

```
python generate_delta_trajectory.py <trajectory.hdf5> [options]
```

### Delta Format (calibration-safe)

```
REF[13]        = frame 0 — absolute SCS values for the starting stance
DELTA[N-1][13] = frames 1..N-1 — signed int16 offsets from REF
MOVE_MS[N]     = move time per frame (ms)
DELAY_MS[N]    = dwell time per frame (ms)
```

At runtime the firmware computes: `frame[f][id] = REF[id] + DELTA[f-1][id]`.

**After recalibration you only update `REF[]`.** The deltas never change
because they encode RELATIVE joint motion, not absolute positions. This is
the same design as `BF3_REF` / `BF3_DELTA` in `hardcode_backflip_angle.h`.

### Options

| Flag | Default | Description |
|---|---|---|
| `--name NAME` | derived from filename | C identifier prefix (e.g. `HDF5_TRAJ1`) |
| `-o DIR` | `../main/` | Output directory |
| `--frames N` | all | Only process first N frames |
| `--move-ms MS` | from HDF5 timing | Fixed move time per frame (overrides HDF5 dt) |
| `--delay-ms MS` | `0` | Fixed dwell time per frame |
| `--speed F` | `1.0` | Time multiplier (`2.0` = 2x faster) |
| `--min-move-ms MS` | `10` | Minimum move time, floors the HDF5-derived value |
| `--flip-left` | off | Negate left-side DELTAs (FL/RL HFE+KFE) — use for asymmetric trajectories where left legs move opposite to expected |

### Examples

```bash
# Generate calibrated delta header from the backflip trajectory:
python generate_delta_trajectory.py bfv1.hdf5 --name HDF5_TRAJ1 -o ../main/

# Asymmetric trajectory (e.g. backflip): flip left side for correct mirroring:
python generate_delta_trajectory.py bfv1.hdf5 --name HDF5_TRAJ1 -o ../main/ --flip-left

# Limit to 28 frames with fixed 100ms move time:
python generate_delta_trajectory.py traj.hdf5 --frames 28 --move-ms 100

# Speed up 2x:
python generate_delta_trajectory.py traj.hdf5 --speed 2.0

# With a dwell/pause between frames:
python generate_delta_trajectory.py traj.hdf5 --delay-ms 50
```

### Firmware integration (4 steps)

1. Generate the header into `main/`
2. Add `#include "my_traj.h"` in `main.c`
3. Copy the `load_hdf5_traj1()` pattern, replacing `HDF5_TRAJ1_*` with `MY_TRAJ_*`:
   ```c
   static void load_my_traj(void){
       int nf = MY_TRAJ_FRAMES < MAX_FRAMES ? MY_TRAJ_FRAMES : MAX_FRAMES;
       for(int f=0; f<nf; f++){
           for(int id=1; id<=12; id++)
               rec_frames[f][id] = (uint16_t)((int)MY_TRAJ_REF[id] + (f==0 ? 0 : (int)MY_TRAJ_DELTA[f-1][id]));
           frame_move_ms[f]  = MY_TRAJ_MOVE_MS[f];
           frame_delay_ms[f] = MY_TRAJ_DELAY_MS[f];
       }
       rec_count = nf; verify_idx = 0; use_frame_timing = 1;
   }
   ```
4. Add HTTP handlers + `reg()` calls + web UI buttons (copy the `/hdf5traj1load` pattern)

## `extract_hdf5.py` — Inspection & Debug

```
python extract_hdf5.py <trajectory.hdf5> [options]
```

For inspecting trajectory data or exporting to debug formats. Also supports
the older **absolute-format** C header (`mp2_backflip_data.h` style), but the
delta format from `generate_delta_trajectory.py` is preferred for firmware use.

### Output Options (pick at least one)

| Flag | Output |
|---|---|
| `--summary` | Human-readable overview (default if nothing else given) |
| `--header NAME` | C header `NAME_data.h` — absolute URDF-degree format |
| `--json FILE` | JSON with per-frame angles, timestamps, optional torques |
| `--csv FILE` | CSV, one row per frame, columns = servo names |

### Other Options

| Flag | Effect |
|---|---|
| `--scs` | Output SCS servo units (0–1023) instead of degrees |
| `--raw` | Keep optimizer-native URDF angles (skip auto-calibration) |
| `--include-torques` | Add torque data to JSON output |
| `--no-timestamps` | Omit the `time_s` column from CSV/JSON |
| `--standing-hfe DEG` | Manually set standing HFE (overrides auto-detect) |
| `--standing-kfe DEG` | Manually set standing KFE |
| `-o DIR` | Output directory |
| `--frames N` | Only export first N frames |

### Examples

```bash
# Inspect a trajectory:
python extract_hdf5.py backflip_v4.hdf5 --summary

# Export angles as CSV for external analysis:
python extract_hdf5.py trajectory.hdf5 --csv debug.csv

# Export SCS values as CSV:
python extract_hdf5.py trajectory.hdf5 --csv debug.csv --scs

# Generate absolute-format C header (legacy style):
python extract_hdf5.py bfv1.hdf5 --header BF_V1 -o ../main/

# Export raw optimizer-native angles as JSON:
python extract_hdf5.py trajectory.hdf5 --json raw.json --raw
```

## `flash_trajectory.py` — Real-Time Streaming & Buffer Loading

```
python flash_trajectory.py <trajectory.hdf5> [options]
```

Streams trajectory frames to a running ESP32 over WiFi, or loads them into the
teach/record buffer for Web UI playback.

### Three Workflows

| Mode | What it does | Frame limit |
|---|---|---|
| `--generate` | Creates C header file for firmware compilation | Unlimited |
| `--upload` | Streams frames to ESP32 in real time via HTTP `/leg` endpoint | Unlimited |
| `--load` | Loads frames into teach/record buffer (then use Web UI Play) | **128** (ESP32 MAX_FRAMES) |

### Connection Options

| Flag | Default | Description |
|---|---|---|
| `--host IP` | `192.168.4.1` | ESP32 IP (AP mode default) |
| `--port N` | `80` | HTTP port |
| `--dry-run` | off | Print what would be sent without connecting |

### Playback Options

| Flag | Default | Description |
|---|---|---|
| `--speed F` | `1.0` | Playback speed multiplier (>1 = faster, <1 = slower) |
| `--frames N` | all | Only process first N frames |

### Examples

```bash
# Stream trajectory to robot in real time:
python flash_trajectory.py flip.hdf5 --upload --host 192.168.1.100

# Preview the first 10 frames offline:
python flash_trajectory.py flip.hdf5 --upload --dry-run --frames 10

# Play at 2x speed:
python flash_trajectory.py flip.hdf5 --upload --host 192.168.1.100 --speed 2.0

# Load first 28 frames into the teach buffer for Web UI playback:
python flash_trajectory.py flip.hdf5 --load --host 192.168.1.100 --frames 28
```

## Angle Convention & Auto-Calibration

The trajectory optimizer outputs joint angles in the **URDF's native joint-zero
convention**, which differs from the **BF_STAND convention** the ESP32 firmware
expects.  For example, the standing pose might be HFE = +57deg in the optimizer
but HFE = -90deg in BF_STAND -- the same physical posture, different reference.

### How the tools handle this

1. **The first frame of every HDF5 is the initial/standing pose.**
2. The tools auto-detect that frame's HFE/KFE as the **standing reference**.
3. They compute the offset:  `bf_deg = opt_deg - standing_opt + BF_STAND`.
4. For real-time upload:  `servo_deg = 135 + BF_SIGN x (opt_deg - standing_opt)`.
5. For delta headers: the conversion goes all the way to SCS, then frame 0
   becomes `REF[]` and all other frames become `DELTA[][]` (signed offsets
   from REF).

This means:

- **Delta headers** are calibration-safe -- only `REF[]` changes after recalibration.
- **Real-time uploads** send absolute servo degrees (0-270) where 135deg = center.
- Left/right mirroring is handled automatically via `BF_SIGN`.
- **`--raw`** skips calibration if you want the raw optimizer angles.

### Manual override

If the first frame is not the standing pose (e.g. the trajectory starts from a
crouch), provide the standing angles manually:

```bash
# For extract_hdf5.py (available now):
python extract_hdf5.py traj.hdf5 --header MY --standing-hfe 56.95 --standing-kfe -101.24

# For generate_delta_trajectory.py (coming soon):
python generate_delta_trajectory.py traj.hdf5 --standing-hfe 56.95 --standing-kfe -101.24
```

## Servo Order (12-column format)

| Col | Servo ID | Joint | HDF5 q index (14-DOF) | HDF5 q index (18-DOF) |
|-----|----------|-------|----------------------|----------------------|
| 0 | 1 | FR_abd | -- (always 0) | -- (skipped) |
| 1 | 2 | FR_HFE | 6 | 7 |
| 2 | 3 | FR_KFE | 7 | 8 |
| 3 | 4 | FL_abd | -- (always 0) | -- (skipped) |
| 4 | 5 | FL_HFE | 8 | 10 |
| 5 | 6 | FL_KFE | 9 | 11 |
| 6 | 7 | RR_abd | -- (always 0) | -- (skipped) |
| 7 | 8 | RR_HFE | 10 | 13 |
| 8 | 9 | RR_KFE | 11 | 14 |
| 9 | 10 | RL_abd | -- (always 0) | -- (skipped) |
| 10 | 11 | RL_HFE | 12 | 16 |
| 11 | 12 | RL_KFE | 13 | 17 |

- **14-DOF** = Mini Pupper reduced model (hips locked out, q shape `(n,14)`)
- **18-DOF** = Solo12 full model (q shape `(n,18)`) -- HAA (abduction) indices skipped
- Both formats are **auto-detected** from `q.shape[1]`.
